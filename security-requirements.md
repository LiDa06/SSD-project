# Требования безопасности

| ID | Требование | Критерий приёмки | Связанные T / D |
| --- | --- | --- | --- |
| SR-01 | Система должна разрешать клиенту просматривать и отменять только те заказы, владельцем которых является текущий аутентифицированный клиент. | Клиент A создаёт заказ. Клиент B пытается получить данные этого заказа или отменить его по известному идентификатору. Система отклоняет действие, данные и состояние заказа не изменяются. Клиент A может просмотреть свой заказ и, если он находится в статусе `Created`, отменить его. | T-01, D-01 |
| SR-02 | Сервер должен определять цену каждой позиции и итоговую стоимость заказа на основе актуальных данных каталога. Значения цены или стоимости, переданные клиентом в запросе, игнорируются и не сохраняются. | Клиент создаёт заказ, передав только идентификаторы товаров и количество. Сервер подставляет цены из каталога и возвращает корректную итоговую стоимость. Если клиент дополнительно передаёт цену или итог, эти значения игнорируются, а в заказе сохраняются цены каталога. | T-03, D-02 |
| SR-03 | Только пользователь с ролью Employee может принимать заказ в работу и завершать его обработку. Завершить заказ может только сотрудник, который ранее принял этот заказ. Роль и идентификатор сотрудника сервис определяет по текущему аутентифицированному пользователю, а не по полям запроса. | Запросы клиента Customer на принятие или завершение заказа отклоняются без изменения заказа. Если заказ в Processing закреплён за сотрудником A, попытка сотрудника B завершить его отклоняется; сотрудник A может завершить его. | T-05, T-06, T-07, D-01, D-03 |
| SR-04 | При создании заказа система должна определять его владельца по текущему аутентифицированному клиенту и не должна позволять клиенту назначить владельцем другого пользователя через данные запроса. | Клиент A отправляет запрос на создание заказа и пытается указать в нём идентификатор клиента B как владельца. Система либо игнорирует такое значение, либо отклоняет запрос; успешно созданный заказ может принадлежать только клиенту A. | T-02, D-01 |
| SR-05 | Изменять каталог — создавать и редактировать товары, менять цену и признак доступности — может только пользователь с ролью Employee. Клиент не может изменять каталог ни при каких условиях, даже если запрос содержит корректные данные товара. | Клиент пытается создать товар, изменить цену или изменить доступность. Система отклоняет запрос, каталог не изменяется. Сотрудник выполняет те же операции успешно. Неаутентифицированный запрос на изменение каталога отклоняется. | T-04, D-01 |
| SR-06 | Сервис допускает изменение состояния заказа только по переходам Created → Processing, Processing → Completed и Created → Cancelled. Перед изменением сервис проверяет текущее состояние заказа; из Completed и Cancelled переходы запрещены. | Принятие заказа в Created, завершение в Processing и отмена в Created приводят к указанным переходам при наличии нужных прав. Попытки завершить заказ в Created, принять заказ в Cancelled, отменить заказ в Processing и изменить заказ в терминальном состоянии отклоняются; состояние в БД остаётся прежним. | T-06, D-03 |
| SR-07 | Сервис должен создавать заказ только из существующих и доступных товаров с положительным количеством каждой позиции: товар существует, доступен, количество положительное. При любой невалидной позиции заказ целиком не создаётся. | Если при создании заказа передан несуществующий productId, недоступный товар или количество quantity ≤ 0, сервис отклоняет запрос; Order и связанные OrderItem для такого запроса не создаются. Если запрос содержит и корректные, и невалидные позиции, заказ целиком не создаётся, включая корректные позиции. | T-08, D-02 |
