# Требования безопасности

| ID | Требование | Критерий приёмки | Связанные T / D (позднее) |
| --- | --- | --- | --- |
| SR-01 | Система должна разрешать клиенту просматривать и отменять только те заказы, владельцем которых является текущий аутентифицированный клиент. | Клиент A создаёт заказ. Клиент B пытается получить данные этого заказа или отменить его по известному идентификатору. Система отклоняет действие, данные и состояние заказа не изменяются. Клиент A может просмотреть свой заказ и, если он находится в статусе `Created`, отменить его. | — |
| SR-02 | Какое защитное свойство обязательно и при каких условиях | Ситуация и ожидаемый наблюдаемый результат | — |
| SR-03 | Только пользователь с ролью Employee может принимать заказ в работу и завершать его обработку. Завершить заказ может только сотрудник, который ранее принял этот заказ. Роль и идентификатор сотрудника сервис определяет по текущему аутентифицированному пользователю, а не по полям запроса. | Запросы клиента Customer на принятие или завершение заказа отклоняются без изменения заказа. Если заказ в Processing закреплён за сотрудником A, попытка сотрудника B завершить его отклоняется; сотрудник A может завершить его. | — |
| SR-04 | При создании заказа система должна определять его владельца по текущему аутентифицированному клиенту и не должна позволять клиенту назначить владельцем другого пользователя через данные запроса. | Клиент A отправляет запрос на создание заказа и пытается указать в нём идентификатор клиента B как владельца. Система либо игнорирует такое значение, либо отклоняет запрос; успешно созданный заказ может принадлежать только клиенту A. | — |
| SR-05 | Какое защитное свойство обязательно и при каких условиях | Ситуация и ожидаемый наблюдаемый результат | — |
| SR-06 | Сервис допускает изменение состояния заказа только по переходам Created → Processing, Processing → Completed и Created → Cancelled. Перед изменением сервис проверяет текущее состояние заказа; из Completed и Cancelled переходы запрещены. | Принятие заказа в Created, завершение в Processing и отмена в Created приводят к указанным переходам при наличии нужных прав. Попытки завершить заказ в Created, принять заказ в Cancelled, отменить заказ в Processing и изменить заказ в терминальном состоянии отклоняются; состояние в БД остаётся прежним. | — |
